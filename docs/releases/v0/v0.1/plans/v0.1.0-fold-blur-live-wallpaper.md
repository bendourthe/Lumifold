## Overview

Ambient Fold Wallpaper is a specialized Android Live Wallpaper application engineered for Google Pixel foldables (including Pixel Fold, Pixel 9 Pro Fold, and future Pixel foldable hardware). It captures the physical articulation of the device hinge in real time and transforms mechanical posture into a hardware-accelerated depth blur transition. When the device unfolds to 180°, the wallpaper is crisp and clear; as the device folds toward 0°, the wallpaper transitions smoothly into an elevated Gaussian blur with a subtle center zoom (1.04x).

The architecture integrates directly with the Android Open Source Project (AOSP) `WallpaperService` engine. This ensures the live wallpaper executes entirely underneath the user's home screen environment, preserving the official Google Pixel Launcher, app grids, widgets, At a Glance, and gesture navigation without requiring custom launchers or third-party home screen replacements.

Success for v0.1.0 is defined as a production-ready application compiling against Android SDK 35 (minSdk 31 for `RenderEffect`), featuring low-pass filtered hinge tracking, zero battery drain when the display is sleeping or covered, a catalog of landscape and abstract geometric wallpapers, and an interactive test preview activity with a 0° to 180° simulation slider.

## Phase 1: Core Live Wallpaper Engine & Sensor Pipeline

**Goal**: Deliver a stable Android `WallpaperService` engine that tracks physical hinge angles (0° to 180°), applies low-pass noise filtering, calculates an ease-in progress curve, and renders hardware-accelerated blur via `RenderEffect`.  
**Prerequisites**: None.  
**Stability Gate**: Hinge sensor listener registers and outputs smoothed 0° to 180° angles that drive real-time blur adjustments on hardware canvas without dropping below 90 Hz.  
**Verification Expectation**: Run `./gradlew testDebugUnitTest` and observe unit test assertions verifying low-pass filter convergence and non-linear ease-in blur curve calculations.  
**Recommended model tier**: standard  
**Recommended effort level**: medium  
**Rationale**: Involves standard Android Sensor and Graphics APIs with well-defined mathematical formulas.

### Sub-tasks

#### 1.1 -- Hinge Sensor Observer & Curve Filter

**Objective**: Implement `HingeSensorObserver` to register `Sensor.TYPE_HINGE_ANGLE` (sensor type 36), apply an exponential moving-average smoothing filter (factor 0.35), and compute an ease-in progress curve where blur concentrates below 90°.

**Failure modes**:
- If `Sensor.TYPE_HINGE_ANGLE` is absent (emulators without sensor emulation or non-foldable devices), the observer gracefully reports unavailable and provides simulation fallbacks.
- If raw sensor values spike or flutter due to rapid mechanical stops, the filter clamps output strictly between 0.0f and 180.0f.
- If unregister is called repeatedly, no crash or exception occurs.

**Build class**: load-bearing

**Prompt**:
> In `app/src/main/java/com/ambientfold/wallpaper/service/HingeSensorObserver.kt`, implement the hinge sensor observer. Listen for `Sensor.TYPE_HINGE_ANGLE` via `SensorManager`. Apply an exponential moving average: `smoothed = (smoothed * (1 - alpha)) + (raw * alpha)` with alpha = 0.35f. Calculate an ease-in curve `blurProgress = (1.0f - normalizedAngle).pow(1.8f)` so the wallpaper stays sharp across 180° to 90° and progressively blurs between 90° and 0°. Provide `isSensorAvailable` property and a `simulateAngle(degrees: Float)` method.

- [x] T001 [US1] Implement HingeSensorObserver with smoothing filter and ease-in curve calculation app/src/main/java/com/ambientfold/wallpaper/service/HingeSensorObserver.kt

#### 1.2 -- RenderNode Hardware Blur Pipeline

**Objective**: Wire `FoldWallpaperService` to create a hardware `RenderNode` and dynamically apply `RenderEffect.createBlurEffect` clamped up to 42dp, accompanied by a 1.04x center-anchored depth scale.

**Failure modes**:
- If hardware canvas locking fails during rapid surface tear-down, catch the exception cleanly and unlock without crashing the wallpaper service.
- If blur radius is below 0.5dp, set render effect to null to eliminate unnecessary GPU blur shader passes.
- If Android version is below API 31, draw clean fallback bitmap without invoking `RenderEffect`.

**Build class**: load-bearing

**Prompt**:
> In `app/src/main/java/com/ambientfold/wallpaper/service/FoldWallpaperService.kt`, implement the rendering pipeline inside `FoldEngine`. When drawing frames, record into a `RenderNode`, scale canvas by `1.0f + (blurProgress * 0.04f)` anchored at surface center, and draw the wallpaper bitmap. If blur radius > 0.5f, apply `RenderEffect.createBlurEffect(radius, radius, Shader.TileMode.CLAMP)` to the `RenderNode`. Draw the `RenderNode` to hardware canvas via `canvas.drawRenderNode(node)`. Handle surface lock failures gracefully.

- [x] T002 [US1] Implement RenderNode hardware blur and center zoom pipeline in FoldWallpaperService app/src/main/java/com/ambientfold/wallpaper/service/FoldWallpaperService.kt

## Phase 3: Multi-Display Handoff & Battery Cutoff

**Goal**: Deliver seamless display transitions when switching between cover and unfolded displays, along with strict power conservation when displays sleep.  
**Prerequisites**: Phase 2.  
**Stability Gate**: `onSurfaceChanged` caches separate bitmaps for cover and inner displays without memory leaks, and `onVisibilityChanged(false)` completely halts sensor polling.  
**Verification Expectation**: Verify sensor unregistration call when visibility changes to false and assert bitmap cache reuse on surface resizing.  
**Recommended model tier**: strong  
**Recommended effort level**: medium  
**Rationale**: Multi-display lifecycle handling and memory leak prevention in long-running services requires careful resource management.

### Sub-tasks

#### 3.1 -- Dual-Display Bitmap Caching & Surface Handoff

**Objective**: Implement dual-resolution bitmap caching in `FoldWallpaperService` so transitions between cover screen (tall 9:20 aspect) and inner screen (near 1:1 aspect) do not cause allocation pauses.

**Failure modes**:
- If surface dimensions change rapidly during an in-flight fold, recycle previous bitmaps safely without accessing recycled references.
- Bound memory cache to maximum 2 bitmaps (cover + inner) to keep memory footprint under 35 MB.

**Build class**: load-bearing

**Prompt**:
> In `app/src/main/java/com/ambientfold/wallpaper/service/FoldWallpaperService.kt`, implement an in-memory dual display bitmap cache: `coverBitmap` (for aspect ratio > 1.4) and `innerBitmap` (for aspect ratio <= 1.4). In `onSurfaceChanged`, query the cache before re-rasterizing vector drawables. Ensure old bitmaps are properly recycled on wallpaper theme change.

- [x] T007 [US3] Implement dual-display bitmap caching for cover and inner screens app/src/main/java/com/ambientfold/wallpaper/service/FoldWallpaperService.kt

#### 3.2 -- Strict Sensor Lifecycle & Power Conservation

**Objective**: Ensure zero background battery drain by unregistering sensor listeners when the screen turns off, when another app is full screen, or when the wallpaper service is destroyed.

**Failure modes**:
- If device enters Always-On Display (AOD), visibility becomes false, immediately detaching sensor listeners.
- On rapid screen off/on cycles, prevent duplicate listener registrations.

**Build class**: load-bearing

**Prompt**:
> Update `FoldWallpaperService.kt` to enforce strict battery safeguards: on `onVisibilityChanged(false)`, invoke `hingeObserver?.stop()` and clear any pending redraw handler posts. On `onVisibilityChanged(true)`, register sensor listeners only if not already active. In `onDestroy()`, unregister shared preference listeners and recycle all cached bitmaps.
